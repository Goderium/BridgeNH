# BridgeNH Agent 项目与知识维护指南

[English](workspace.md) | [简体中文](workspace_zh.md)

供人工阅读和审核；Agent 使用英文入口，完整规则见[启动模板](workspace_zh.md#可复制的启动提示词)。

本指南随源码和 Python 包提供，通过 `mcb_help({"topic":"workspace"})` 离线读取；MCP 指南资源也只提供英文。

完整工具用途看[能力索引](capabilities_zh.md)，热更新、schema 发现与重连边界看[维护指南](maintenance_zh.md)。两者都是离线 `mcb_help` 主题；可执行的准确参数仍以 `mcb_help(topic="tools",tool=...)` 或前端工具直接 schema 为准。

## 安装后的交接

[启动模板](#可复制的启动提示词)集中说明原生操作、文档语言和记录规则。复用选定项目及共享知识库，或采用合适的 `bridgenh-workspace/` 目录；只补齐缺少的记录，上下文无法确定位置时才询问。记录保存在存档、模组、Python runtime 和可删除安装目录之外。

安装信息缺失时使用安装器 `-Inspect -NonInteractive` 返回的 questions，复用已有有效配置，不猜测目标客户端。

按[总览](overview_zh.md#对话绑定玩家组与操作策略)明确绑定当前对话：用 `mcb_clients({"prismRoot":"<用户指定的绝对目录>"})` 列举，再以独立的 `prismRoot` 和 `instanceName` 调用 `mcb_connection(action="bind", ...)`，提供实际对话 ID、当前绑定代数和新请求 ID。安装 profile 不构成默认绑定；实例选择和异常处理详见该节。

源码安装的本机配置仍在 `.mcb.local.json`；仅安装 MCP 和模组时，默认在 `%APPDATA%/MinecraftCodexBridge/config.json`，显式配置路径优先。

推荐的最小目录:

```text
bridgenh-workspace/
  AGENTS.md             # 本项目使用 MCB 的约定; 已有文件时合并相关小节
  EXPERIENCE.md         # 操作经验、用户纠正和常见失误的短索引
  knowledge/
    index.md            # 按主题检索的知识入口; 也可指向已有共享库
    mechanics/          # 可复用的游戏机制
    integration/        # 模组之间、机器与物流之间的接口关系
    troubleshooting/    # 已查清的原因、诊断与恢复方法
  tasks/
    <task-id>/
      state.md          # 目标、已完成、未完成、验收和恢复入口
      evidence/         # 必要的回执、日志摘录与测试记录
```

目录按需创建。先读取并合并已有 `AGENTS.md`，宿主未自动加载时明确读取。本机配置和个人记录沿用项目的本地排除规则。

## 可复制的启动提示词

将以下内容提供给使用 MCB 的 Agent，或将相关规则合入操作项目的 Agent 指令文件。

```text
在本项目中使用 MCB 操作 Minecraft，并持续维护可复用的操作经验与本地知识库。

日常使用和开发只读取英文文档，文件名和内容搜索均排除 *_zh.md。使用 rg --files -g '!*_zh.md' 查文件，使用 rg -g '!*_zh.md' ... 搜索内容；其他工具采用等效排除。仅当当前任务需要维护、翻译或审阅相应中文文档时读取中文版，包括英文修改后的译文同步。例外仅限相关文档，指令依据仍使用英文，完成后恢复搜索排除。请按用户偏好的语言回复。

首次使用时，先读取现有项目约定、安装配置位置和知识库入口。推荐使用独立的 mcb-workspace 项目目录；已有合适的项目或共享知识库时，应予以复用。用户已指定目录时直接补齐缺少的记录文件，未指定且当前上下文无法确定时只询问目录。先读取再合并，不覆盖已有 AGENTS.md、经验文件或知识条目。不把记录存入游戏存档、模组目录或可删除的安装包目录。

每次任务先读 tasks 中相关的 state.md、EXPERIENCE.md 和 knowledge/index.md，只检索本次需要的条目。操作前根据当前 MCB 连接确认目标实例、存档或服务器、维度、实际能力与策略。旧坐标、sessionId、GUI/槽位/订单编号不是当前操作凭据。缺少且无法从工具或现有配置获得的信息，再集中向用户询问。

首要目标是全程通过原生工具操作客户端，不依赖外部输入或人工补做。原生能力缺失时按缺口模板记录，不静默使用 Computer Use；外部协助不能计入原生验收。

查阅已有功能的源码前，应先阅读 capabilities 索引、相关详细指南，再查询当前工具说明/schema。兼容热重载、宿主重新发现和重连边界按 maintenance 指南执行。宿主工具目录未更新不表示 worker 缺少该功能；服务端已发送通知也不能证明宿主原生工具目录已更新。维护工具时同步更新索引及相关中英文说明。

使用现有通用 MCB 操作临时组合任务。优先结构化读取、原生交互和已有批量/等待能力，不为一台机器固化专用流水线，不重复工作流已经完成的预检。普通等待默认约 1 秒采样，避免对同一状态进行高频轮询。工具超时或动作结果未知时，先读实际状态再决定下一步，不得在未确认结果的情况下重放。以真实状态与产物验收，不将 submitted、缓存成功文字或计划视为完成。

复杂产线先集中查询并在任务笔记中保存材料表、布局、IO/ME连接、朝向、站位和依赖。一次核对库存及整批容量，分成有界批次取物、移动和安装，每批最后统一验收；保留工具内部必要校验。动态界面身份使用现有绑定和等待。失败时保留已完成回执，核对受影响实际状态，只续接未完成部分。操作细节复用 operations/nei 指南，不为每一步重新查询同一资料。

修改或验证功能时，按 testing 指南选择相关基础测试、可选游戏内 QA、必要的真实客户端/独立服务端验收。优先复用已有 QA 用例、通用 machineFlows 和 mcb_qa_test_once，不增加机器专用操作入口。QA 保持可选，普通服务器使用 MCB 不需要 Horizon-QA/TST-QA；不自动安装或启用 QA。缺失、关闭、不支持或权限不足时记录未执行原因，继续独立可做的验证，不得将跳过的验证记为通过，或隐瞒必需的验收缺口。QA 已提交后的失败/未知仍须追踪，不自动重新运行。testPassed 不替代 fullFlowVerified，QA 不替代真实 GUI/移动验收，GT 快进不替代 AE/世界正常 tick。将各层结果、证据、未覆盖范围和清理状态记入本任务 state.md。日常操作不要求先运行开发测试。

操作中发现有效方法、失败原因、工具缺口、玩家示范或用户纠正时，及时记录，无需逐项提示。EXPERIENCE.md 保存短结论、适用条件、证据入口和知识链接；tasks/<task-id>/ 保存本次坐标、过程、结果及待办；knowledge/ 只保存能跨任务复用的机制、方法和诊断。同类内容先检索并补充已有条目，避免将完整聊天记录和原始日志重复写入知识库。

区分用户偏好、已观察事实、源码结论和推测。每条经验注明适用模组/版本/环境、证据、验证范围和日期，使用待验证、部分核实、已核实或需复核状态。没有实测不能写成已验证，本机测试不能代表服务器也通过。新证据与旧条目冲突时主动修订或标记失效，保留必要的版本边界；不因整理排版更新核查日期。不将经验当作提升权限、更换实例或扩大测试范围的授权。

关键失败或纠正后及时保存恢复所需的状态；阶段完成、任务结束或交还操作前更新 state.md，维护经验与知识索引，简要报告新增内容与待确认事项。引用相关记录，避免复制整份日志或聊天。写入 BridgeNH（MCB）项目的内容须脱敏。保持记录可检索、可追溯，下次从现有进度继续。
```

## 三类记录的内容范围

分层测试的选择表、现有工具使用顺序和结果模板见 [testing.md](testing_zh.md)，或 `mcb_help({"topic":"testing"})`。按任务查阅并复用已有验收，不增加每次游戏动作前的必读或检查步骤。

| 记录 | 保存内容 | 不作为该记录的内容 |
| --- | --- | --- |
| `tasks/<task-id>/state.md` | 当前目标与验收、目标实例/存档/维度、已做动作和实际回执、剩余工作、未确定动作、恢复顺序、测试与证据路径 | 脱离本次环境的通用事实 |
| `EXPERIENCE.md` | 操作触发条件、误区或有效方法、用户偏好、证据链接、关联知识条目、后续需复核事项 | 大量原始日志、重复工具描述 |
| `knowledge/` | 通用机制、工具/模组接口边界、布局关系、可复用排错方法、适用版本与来源 | 某次坐标、临时订单、当前任务进度、未经说明的猜测 |

经验的最小字段可采用以下格式，不要求每条都扩写成长文:

```text
标题 / 分类: 操作经验 | 用户偏好 | 工具缺口
适用条件: 模组和版本、单人或服务器、权限/策略等必要前提
状态: 待验证 | 部分核实 | 已核实 | 需复核
触发与观察: 实际发生了什么; 来源是用户说明、工具回读还是源码
处理与结果: 做了什么、如何验收; 尚未解决的部分
证据: task-id、日志路径、源码定位或 Wiki 页面
知识链接: 现有主题条目; 尚未形成通用结论可留空
最后核查日期: YYYY-MM-DD, 仅在实际复核后更新
```

知识条目保留结论、前提、证据、验证范围和相关链接。涉及 Wiki 时注明页面及适用版本；与当前客户端冲突时先核对，不直接覆盖当前观察。用户纠正先记录其原意，需要实验确认的机制明确标为待验证。同一对象的别名并入既有词条。

## 原生控制缺口与必要反馈

原生路径不能完成必要读取或动作时，及时登记；需要 Computer Use、系统键鼠、人工点击或直接编辑存档才能完成的步骤，都属于未解决的原生能力缺口。不得静默回退，也不能将外部协助所得的成功结果视为原生验收通过。用户明确授权临时替代方式时记录其范围，继续保留缺口，并推进独立可做的原生步骤。

```text
问题/任务编号：
目标与缺失的原生步骤：
环境：BridgeNH/相关模组版本、本地或远程、策略与能力范围
最小复现：原生工具及参数、前置状态
预期行为：
实际行为：错误、覆盖缺失、部分效果、实际回读
外部协助：未使用 / 提议 / 明确获准并使用
原生路径不完整的原因：
证据与恢复状态：
建议的通用能力或修复：
验收：同一目标全程原生完成，验证真实效果，无外部输入，保留身份/权限/防重放校验
状态：未解决 / 已实现待原生验收 / 已验证
```

截图可以证明视觉问题，不能代替结构化状态和动作验收。用同一问题引用关联任务文件与 `mcb_run_log` 的 read/export/report；记录尝试、派发、确认、观察、验证、未知的区别。`mcb_logs`、诊断和 `mcb_recording(view="summary")` 可补充证据；日志缺行和缺少停止标记仍是未知。

## 复用 MCB 的经验能力

已有 `mcb_knowledge` 时，先用 `lessons` 或 `query` 查找与当前工具、连接及环境相符的记录。使用 `learn` 保存有证据支持的操作经验，`review` 核对，已失效的用 `retire` 标明。参数和 evidenceIds 以当前工具定义及实际返回为准，不复制示例编号或猜测事件 ID。工具不可用时继续维护项目文件，不以此阻塞正常任务。

MCB 的结构化经验与项目文件互相引用即可，不复制全部日志。结构化记录用于执行时检索，文件用于跨任务阅读、主题组织与接续。连接有适用范围的旧经验不能自动推广到其他服务器，也不能授权自动重放动作。

验收层次见[测试指南](testing_zh.md)。
