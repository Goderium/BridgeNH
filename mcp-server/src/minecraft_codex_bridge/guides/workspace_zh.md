# BridgeNH Agent 项目与知识维护指南

本指南随源码和 Python 包提供。`mcb_help({"topic":"workspace"})` 和对应的 MCP 指南资源均可离线读取中文正文。

完整工具用途看[能力索引](capabilities_zh.md)，热更新、schema 发现与重连边界看[维护指南](maintenance_zh.md)。两者都是离线 `mcb_help` 主题；可执行的准确参数仍以 `mcb_help(topic="tools",tool=...)` 或前端工具直接 schema 为准。

## 安装后的交接

[启动模板](#可复制的启动提示词)集中说明原生操作、文档语言和记录规则。复用选定项目及共享知识库，或采用合适的 `bridgenh-workspace/` 目录；只补齐缺少的记录，上下文无法确定位置时才询问。记录保存在存档、模组、Python runtime 和可删除安装目录之外。

安装信息缺失时使用安装器 `-Inspect -NonInteractive` 返回的 questions，复用已有有效配置，不猜测目标客户端。

按[总览](overview_zh.md#对话绑定玩家组与操作策略)明确绑定当前对话：用 `mcb_clients({"prismRoot":"<用户指定的绝对目录>"})` 列举，再以独立的 `prismRoot` 和 `instanceName` 调用 `mcb_connection(action="bind", ...)`，提供实际对话 ID、当前绑定代数和新请求 ID。安装 profile 不构成默认绑定；实例选择和异常处理详见该节。

源码安装的本机配置仍在 `.mcb.local.json`；仅安装 MCP 和模组时，默认在 `%APPDATA%/MinecraftCodexBridge/config.json`，显式配置路径优先。

推荐的最小目录:

```text
bridgenh-workspace/
  AGENTS.md             # 本项目使用 MCB 的约定; 已有文件时合并相关小节
  EXPERIENCE.md         # 操作经验、用户纠正和常见失误的短索引
  knowledge/
    index.md            # 按主题检索的知识入口; 也可指向已有共享库
    mechanics/          # 可复用的游戏机制
    integration/        # 模组之间、机器与物流之间的接口关系
    troubleshooting/    # 已查清的原因、诊断与恢复方法
  tasks/
    <task-id>/
      state.md          # 目标、已完成、未完成、验收和恢复入口
      evidence/         # 必要的回执、日志摘录与测试记录
```

目录按需创建。先读取并合并已有 `AGENTS.md`，宿主未自动加载时明确读取。本机配置和个人记录沿用项目的本地排除规则。

## 可复制的启动提示词

将以下内容提供给使用 MCB 的 Agent，或将相关规则合入操作项目的 Agent 指令文件。

```text
使用 BridgeNH 原生工具操作选定的 GTNH 客户端。通过 mcb_help 读取中文操作指南。BridgeNH 的其他项目文档以英文为准，翻译或审核时再查阅对应译本。回复使用用户偏好的语言。

读取项目既有约定、相关任务状态和经验索引。在选定工作区合并记录，存放位置应独立于游戏存档、已安装模组和临时安装包。

用 mcb_packdata 查已发布的任务、指南和配方，用 mcb_plan_production 规划定量订单，配方变动从客户端 NEI 核对。可复用的操作方法查 mcb_knowledge，当前库存、机器状态及操作结果从游戏读取。按用途在能力索引中定位工具，再用 mcb_help 查询准确参数。按当前操作查阅专项指南。

操作游戏时，将当前对话绑定到指定的 Prism 目录和实例名，核对会话、存档或服务器、维度、生效策略及相关能力。操作目标和 GUI 标识取自当前观察。工具和既有配置均无法提供必要信息时，再向用户询问。

一次规划材料、布局、通路和依赖。已有专用接口时须直接调用，虚拟鼠标仅用于接口未覆盖的界面手势或专门的指针测试。复用批量操作、有时限的等待及内置校验。部分完成、超时或效果不明时，先核对原动作以及库存或世界的实际变化，再续接剩余操作。以同步后的状态及实际收到的产物验收。

必要步骤必须借助 Computer Use 时，立即主动告知用户，并按工作区指南登记为错误。只读检查、准备和排障同样适用。记录实际使用的人工协助。按测试指南选择相关验证，沿用既有权限和选定世界，注明待完成的原生验收。

任务状态保存进展、待确认事项和恢复步骤，EXPERIENCE.md 保存简短经验，knowledge/ 保存可复用机制。注明来源、版本和验证范围，区分实际观察、推测和用户偏好。交接时更新索引并链接证据。写入 BridgeNH 项目的资料须脱敏。修改工具时同步能力索引与双语指南，并按维护指南验证已加载的工具目录。
```

## 三类记录的内容范围

分层测试的选择表、现有工具使用顺序和结果模板见 [测试指南](testing_zh.md)，或 `mcb_help({"topic":"testing"})`。按任务查阅并复用已有验收，不增加每次游戏动作前的必读或检查步骤。

| 记录 | 保存内容 | 不作为该记录的内容 |
| --- | --- | --- |
| `tasks/<task-id>/state.md` | 当前目标与验收、目标实例/存档/维度、已做动作和实际回执、剩余工作、未确定动作、恢复顺序、测试与证据路径 | 脱离本次环境的通用事实 |
| `EXPERIENCE.md` | 操作触发条件、误区或有效方法、用户偏好、证据链接、关联知识条目、后续需复核事项 | 大量原始日志、重复工具描述 |
| `knowledge/` | 通用机制、工具/模组接口边界、布局关系、可复用排错方法、适用版本与来源 | 某次坐标、临时订单、当前任务进度、未经说明的猜测 |

经验的最小字段可采用以下格式，不要求每条都扩写成长文:

```text
标题 / 分类: 操作经验 | 用户偏好 | 工具缺口
适用条件: 模组和版本、单人或服务器、权限/策略等必要前提
状态: 待验证 | 部分核实 | 已核实 | 需复核
触发与观察: 实际发生了什么; 来源是用户说明、工具回读还是源码
处理与结果: 做了什么、如何验收; 尚未解决的部分
证据: task-id、日志路径、源码定位或 Wiki 页面
知识链接: 现有主题条目; 尚未形成通用结论可留空
最后核查日期: YYYY-MM-DD, 仅在实际复核后更新
```

知识条目保留结论、前提、证据、验证范围和相关链接。涉及 Wiki 时注明页面及适用版本；与当前客户端冲突时先核对，不直接覆盖当前观察。用户纠正先记录其原意，需要实验确认的机制明确标为待验证。同一对象的别名并入既有词条。

## 原生控制缺口与必要反馈

一旦发现必要的观察或动作必须借助 Computer Use，立即主动告知用户哪一步受阻、已尝试哪个原生或命令行入口。只读查看桌面、准备环境和排障也按错误处理。用所选实例的 `mcb_run_log` 登记。新建报告须填写 `category`、`title` 和 `observed`。

```json
{"action":"report","category":"error","title":"Desktop required for a readiness check","observed":"Native status did not expose the required readiness state.","expected":"Read readiness through the CLI or native tool."}
```

将返回的 `id` 写入 `tasks/<task-id>/state.md`。以 `action="report"` 和同一 `id` 补充报告，用 `reproduction` 记录版本和复现步骤，`observed` 记录实际桌面操作与回读结果，`suggestion` 说明修复建议和原生复验方法。日志暂不可用时，先将这些内容写入任务状态，在当前对话交付反馈，待日志恢复后补报。

交付时说明本次任务的实际结果、使用的桌面协助和剩余工作，附上证据和未解决的问题 ID 或任务引用。全流程原生验收保持待验证，直至通过预期接口完成同一步骤，并保留身份、权限与防重放校验。其余步骤按各自证据验收。视觉问题可附截图。

绑定客户端的虚拟鼠标属于原生工具。用它弥补专用接口缺失时，记录缺失接口和实际效果。测试目标本身就是指针显示、悬停或点击时，按该指针行为的验收条件记录结果。

## 复用 MCB 的经验能力

已有 `mcb_knowledge` 时，先用 `lessons` 或 `query` 查找与当前工具、连接及环境相符的记录。使用 `learn` 保存有证据支持的操作经验，`review` 核对，已失效的用 `retire` 标明。参数和 evidenceIds 以当前工具定义及实际返回为准，不复制示例编号或猜测事件 ID。工具不可用时继续维护项目文件，不以此阻塞正常任务。

MCB 的结构化经验与项目文件互相引用即可，不复制全部日志。结构化记录用于执行时检索，文件用于跨任务阅读、主题组织与接续。连接有适用范围的旧经验不能自动推广到其他服务器，也不能授权自动重放动作。

用 `mcb_run_log` 读取或导出历史证据。`mcb_logs` 和诊断工具可检查所选客户端的日志与进程，`mcb_recording(view="summary")` 可查被动记录。区分派发、确认、观察、验证和未知；日志缺行或缺少停止标记时，结果仍是未知。

验收层次见[测试指南](testing_zh.md)。
