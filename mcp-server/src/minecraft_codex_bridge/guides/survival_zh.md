# 生存基础操作

绑定目标客户端，读取当前会话、维度、角色、背包和 `lifecycleTarget.expectedWorld`。生存操作使用角色实际持有的物品。通用控件按当前权限供两种游戏模式调用。创造供给和测试服务器规则各有独立入口。

| 目标 | 原生操作与验收 |
| --- | --- |
| 进食与持续补饱 | 见[食物](food_zh.md)。普通食物按份消耗；治愈之斧被选为主手时按物品自身周期回复，切换到其他工具后效果暂停。 |
| 采掘和拾取 | 选中工具，对准已加载方块，向 `mcb_mine` 提供观察到的注册名、元数据、坐标及快捷栏槽位。原生采掘只绑定这个目标，按时限结束。用 `mcb_task_status` 读取任务编号和结束原因。分别确认方块变化、进入拾取距离前后的背包增量。工具自身的范围效果、其他玩家和掉落物消失均会影响结果。 |
| 行走与跟随 | 用 `mcb_navigate`、`mcb_approach` 到达观察到的位置或可交互面。支持的集成世界可用 `mcb_follow` 跟随已加载玩家；远程地面行走按当前能力声明选择。 |
| 物品、装备与动物交互 | 使用 `mcb_hotbar`、实际装备槽和 GUI 点击。对准动物后，向 `mcb_entity_interact` 提供准星目标的 UUID 和维度，可同时绑定手持物。`accepted` 表示客户端回调结果。再次操作前应核对动物和背包的实际变化，例如取得的羊毛及消耗的剪刀耐久。 |
| 放入或取出一组物品 | 从可触及的面打开箱子，读取当前界面、窗口、实际来源槽、物品和光标。原版箱子可用 `mcb_chest_transfer` 执行一次原生 Shift 点击。回执中的数量来自点击当时的客户端容器。客户端预测移动量为零时，服务端仍可能接受点击。再次操作前应核对箱内和背包中已同步的数量。带 NBT 的物品可用 `mcb_gui_tooltip` 查询同一槽位；仅当 `nbtTruncated` 为假时，使用完整的 `item.nbt`。其他容器及拆分物品沿用 `mcb_slot_click`。 |
| 合成或机器加工 | 从[离线资料](packdata_zh.md)或 NEI 选择配方，在实际工作台或机器 GUI 中放入真实材料。检查输出槽并取走产物，核实原料消耗、模具或容器返还及实际收货。已支持的定量加工见[操作指南](operations_zh.md)。 |
| 核验机器工序 | 推进前核对实际投料、机器进度、中间缓存及交付数量。中断后读取当前库存，与任务记录对账。 |
| 使用 ME 终端 | 读取当前终端的同步库存，选中准确资源，使用原生终端动作取放，再核对背包与终端数量。见 [AE2](ae_zh.md)。 |
| 查任务与提交 | 从[离线资料](packdata_zh.md)读取任务定义。用 `mcb_quest_progress` 查询本人进度，按 `mcb_quest_step` 支持的动作单步操作，核实队伍共享进度、实际消耗及所得奖励。 |

## 定量采集与跨仓补料

用 `mcb_survival_order` 建立工单。`mode=gather` 按本单实际交付的数量结算，目标仓已有库存不抵扣。`mode=replenish` 将目标仓的同一物品补足到 `quantity`，按 `sources` 顺序取货。例如目标为 32、仓内已有 20 时，本单还需补 12。数量用十进制字符串；物品按注册名、`damage` 和完整 NBT 匹配，省略 `nbt` 表示仅匹配无标签物品。

```json
{"action":"open","orderId":"iron-refill","mode":"replenish","quantity":"32","item":{"registryName":"minecraft:iron_ingot","damage":0},"sources":[{"kind":"chest","x":10,"y":64,"z":12},{"kind":"chest","x":13,"y":64,"z":12}],"destination":{"kind":"chest","x":16,"y":64,"z":12},"expectedSessionId":"<session>","expectedWorld":"<lifecycleTarget.expectedWorld>","dimension":0}
```

将示例中的会话、世界、维度及坐标换成当前实际值。采集模式用 `gather.bounds` 指定有界区域；采掘方块时另给出方块类型、元数据和工具槽位。仓位字段和采集范围上限见 `mcb_help(topic="tools",tool="mcb_survival_order")`。

原版箱子使用 `kind=chest`。支持的标准有限抽屉使用 `kind=drawer` 并指定分格编号。在线的实体 ME 物品终端使用 `kind=me` 并指定安装面，取放遵循玩家的 ME 网络权限。选择可到达的仓位，并在快捷栏保留空位供开仓。跨仓行走使用当前客户端可用的生存寻路能力。

1. `open` 指定本对话唯一的 `orderId`。`advance` 带最新的 `expectedRevision` 及当前会话、世界和维度，每次推进至多 `maxSteps` 步。
2. 用 `gathered` 查看实际采收入包量，`withdrawn` 查看来源仓出库量，`delivered` 查看本单已送达量。`inTransit` 记录已取但尚未交付的量。`remaining` 为尚缺数量，未取得目的仓基线时为 `null`。部分完成时查 `reason`。
3. 回执丢失时先用 `status` 读取工单。存在 `pending` 时用 `reconcile` 核对该笔变动。重新连接后，提供新的会话与世界标识；核对要求同一实例、对话、角色、服务端或存档及维度。归属或数量仍不确定时，工单维持待核对状态。
4. 两次推进之间可执行其他操作。用 `cancel` 结束已结算的工单，已移动的物品保留在实际位置。

## 连续执行与中途插入

准备好的原生动作可用一次 `mcb_sequence` 连续执行。需要在中途插入工作时，用 `mcb_action_chain` 将任务分成具名步骤组。每组由普通 sequence 步骤组成。每个写动作都需有通过 `accepts` 关联的等待或断言，或动作自身的 `after` 条件。条件应验证实际效果，例如通过新读取的基线与背包增量确认拾取或交付。

1. `open` 校验各组，并绑定声明的会话、世界及维度，返回队列编号和修订号。
2. `advance` 执行下一组并返回回执。调用方可按回执连续推进。原生输入任务仍在运行时，等待该任务结束。
3. 在两组之间用 `insert` 将工作插入待执行列表的开头。例如在采掘和步行之间插入进食，再在需要采掘的组内重选工具。每组读取自身所需的物品、目标和界面标识。已开始的组会完成或按原规则停止。
4. 每次推进、插入或取消均使用最新编号和修订号。返回包丢失时用 `status` 读取最近回执。失败或效果不明时停止续接，先核对现场，再作新的安排。兼容的 worker 热更新保留队列，需显式推进。MCP 重新连接后须重新绑定。

世界切换、玩家接管、原生任务占用分别报告。停止实际按键任务时，用 `mcb_task_cancel` 指定观察到的任务编号。取消待执行队列会丢弃后续工作。
