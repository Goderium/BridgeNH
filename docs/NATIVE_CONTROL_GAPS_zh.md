# 原生客户端控制：能力缺口登记

[English](NATIVE_CONTROL_GAPS.md) | [简体中文](NATIVE_CONTROL_GAPS_zh.md)

验收目标是通过 BridgeNH 原生工具完整操作客户端，不依赖 Computer Use、系统输入或人工补做。本表区分源码/文档已知边界与明确限定范围的实机验收；使用前仍须检查当前能力声明。

## 记录与关闭条件

使用[工作目录指南](../mcp-server/src/minecraft_codex_bridge/guides/workspace_zh.md)中的缺口模板记录证据与恢复信息。

只有目标原生路径在所述环境完成并验证真实效果，才能关闭缺口。模拟测试、人工或 Computer Use 成功均不能单独作为原生验收通过的依据。保留失败或结果未知的操作标识；不得通过更换请求 ID 重试来规避原有结果。

## 已验收原生路径

已通过安装后的 stdio MCP，在 **GT New Horizons 2.9.0（Minecraft 1.7.10、NotEnoughItems 2.8.171-GTNH）** 验证书签的物品/配方创建与删除、同组整配方删除、分组创建/删除、排序、跨页整组移动、显示/合成模式、折叠、数量、保留规则和按任务清理。完整重启客户端后验证了原生保存的页面、分组、物品 NBT 和需求量。清理保留了原有书签与真实库存；重启后临时归属转为未登记并保留。这份验收覆盖已测试操作，不代表所有 NEI 手势或版本。

2026-11-11 在启用 `mcp_tool_list_changed` 的 **Codex 桌面版 26.1103.7773.0** 上完成了工具目录热更新验收。调用 `mcb_backend_restart` 后，新加入的只读探针出现在当前对话的原生工具目录中，并成功完成调用；再次热重启 worker 后，它也从同一目录移除。前端进程与对话绑定保持不变，没有重启 Codex 或 Minecraft，探针没有调用游戏。临时运行文件修改已完整恢复。这项验收关闭了所测试宿主的目录刷新缺口；其他宿主仍须支持 MCP 目录变更通知。稳定前端、初始化说明或依赖变更仍需重新连接 MCP。

2026-11-13 在 GT New Horizons 2.9.0 上完成 BlockRenderer6343 **1.4.25** 预览读取与控制验收。适配器现可读取受保护的元素映射及实例内选择状态。原生方块与控件读取、旋转、缩放、等级切换、选择与清除，以及完整 0..height 层范围均有对应模型回读。全程未使用 Computer Use 或操作系统输入。预览几何不证明世界建造或机器成型；旧 1.4.23 布局具有回归覆盖，不作新增实机验收声明。

2026-11-13 通过 `mcb_action_recovery` 验证了已有回执的创造模式放置恢复：正常放置一次，读取服务器方块，正常移除，重启所选客户端，并通过 worker 热重载保留原未决记录。相同参数的放置在明确核对最新证据之前仍被拦截。恢复本身保持目标为空，随后独立提交相同放置请求成功。目标被占用时核对被拒绝。最终清理保留全部 41 个背包槽及完整 NBT、原支撑和空目标。新增工具无需重启 Codex 即在当前对话中出现并完成调用。适用范围见[恢复流程](../mcp-server/src/minecraft_codex_bridge/guides/maintenance_zh.md#核对已有回执的创造模式放置)。

## 待补齐能力

| 领域 | 当前边界 | 原生验收要求 |
| --- | --- | --- |
| NEI 优选配方树与剩余手势 | favorite 配方树创建及部分组合手势仍未纳入书签管理动作；普通字符回调不能模拟实体快捷键 | 任务需要时提供原生动作、当前身份、有界范围和回读 |
| 第三方 GUI | 已适配控件不代表覆盖所有界面；缺少 coverage 是未知，不是空界面 | 复现缺失控件，补原生读取/操作，并通过 Agent 实际路径验证持久化/效果，无外部输入 |
| 其他未知动作的恢复 | 已验收路径覆盖满足明确证据要求的、已有回执的独立创造模式 ItemBlock 放置。传输结果未知、生存模式消耗及其他修改操作仍受保护。 | 需要时补充对应操作的证据与核对流程；会话变化、修改参数或编辑内部记录均不能证明先前效果。 |
| Prism 启动前对话框 | Windows 与 Prism 11.0.3 实测记录到 Java 启动前的启动器对话框前台及键盘焦点事件，即使操作前后的前台窗口句柄相同。游戏 `windowMode` 控制客户端 SDL 窗口。Prism 的 [CLI 定义](https://github.com/PrismLauncher/PrismLauncher/blob/11.0.3/launcher/Application.cpp)没有静默对话框启动参数。 | 需要启动器支持的后台启动路径，在不修改共享 Prism 进程、不屏蔽其他客户端对话框的条件下保持焦点。游戏窗口验收不关闭此缺口。 |
