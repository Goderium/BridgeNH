# 原生客户端控制：能力缺口登记

[English](NATIVE_CONTROL_GAPS.md) | [简体中文](NATIVE_CONTROL_GAPS_zh.md)

验收目标是通过 BridgeNH 原生工具完整操作客户端，不依赖 Computer Use、系统输入或人工补做。本表区分源码/文档已知边界与明确限定范围的实机验收；使用前仍须检查当前能力声明。

## 记录与关闭条件

使用[工作目录指南](../mcp-server/src/minecraft_codex_bridge/guides/workspace_zh.md)中的缺口模板记录证据与恢复信息。

只有目标原生路径在所述环境完成并验证真实效果，才能关闭缺口。模拟测试、人工或 Computer Use 成功均不能单独作为原生验收通过的依据。保留失败或结果未知的操作标识；不得通过更换请求 ID 重试来规避原有结果。

## 已验收原生路径

已通过安装后的 stdio MCP，在 **GT New Horizons 2.9.0（Minecraft 1.7.10、NotEnoughItems 2.8.171-GTNH）** 验证书签的物品/配方创建与删除、同组整配方删除、分组创建/删除、排序、跨页整组移动、显示/合成模式、折叠、数量、保留规则和按任务清理。完整重启客户端后验证了原生保存的页面、分组、物品 NBT 和需求量。清理保留了原有书签与真实库存；重启后临时归属转为未登记并保留。这份验收覆盖已测试操作，不代表所有 NEI 手势或版本。

2026-11-11 在启用 `mcp_tool_list_changed` 的 **Codex 桌面版 26.1103.7773.0** 上完成了工具目录热更新验收。调用 `mcb_backend_restart` 后，新加入的只读探针出现在当前对话的原生工具目录中，并成功完成调用；再次热重启 worker 后，它也从同一目录移除。前端进程与对话绑定保持不变，没有重启 Codex 或 Minecraft，探针没有调用游戏。临时运行文件修改已完整恢复。这项验收关闭了所测试宿主的目录刷新缺口；其他宿主仍须支持 MCP 目录变更通知。稳定前端、初始化说明或依赖变更仍需重新连接 MCP。
